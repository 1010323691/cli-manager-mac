# claude-cli：用Claude CLI的 CLI 处理任务

后端脚本位于 `~/.claude/skills/cli-manager/backends/claude/`，但**一律经统一入口调用**：下文 `$D` 指 `~/.claude/skills/cli-manager/scripts/cli_delegate.py`，其中 `run` 要加 `--backend claude`。
它负责：
- 清理宿主会话注入的环境变量，防止子进程沿用当前账号、网关、思考强度和会话通道；
- 使用配置的 CLI 配置目录（`CLAUDECLI_CONFIG_DIR` 或 `~/.cli-delegate/config.json`，否则 CLI 默认），在指定工作目录里启动 `claude -p`；
- 通过审批通道 `scripts/approval_mcp.py`（作为 `--permission-prompt-tool` 接入），把子会话的权限请求和 AskUserQuestion 提问转给主会话；
- 记录完整事件流，解析结果并打印中文摘要。

CLI 参数和环境变量的细节见 [../../references/claude-notes.md](../../references/claude-notes.md)，需要透传参数或排查问题时再读。

## 调用方式：主会话直接运行

主会话自己通过统一入口运行脚本，不再派包装子智能体：启动用 `run_in_background: true` 放后台，再循环 `watch` → 审核 → `decide`。完整的主会话流程（写简报、选参数、审批、推送通知、续跑、汇报）见 [../../SKILL.md](../../SKILL.md)「调用方式：主会话直接运行」，下文第 1–8 步是各步骤的细节。

**注意：** 只通过统一入口 `scripts/cli_delegate.py` 调用，**不要直接调用本后端脚本**，也不要为它整体放行（`delegate.py *` / `codex_delegate.py *` 这类规则会把敏感参数一并放开）。权限放行按 SKILL.md「配置与安装」的子命令清单逐条配置。

## 硬性约束

1. **工作目录必须与调用会话相同**：始终显式传 `--cwd "<本会话的主工作目录>"`，即系统提示 Environment 里的 *Primary working directory*（或用户切换后的项目目录）。不要依赖 Bash 当前的 `cd` 位置，也不要传 scratchpad 目录。需要额外目录用 `--add-dir`。
2. **只在用户要求时调用**，它花的是Claude CLI的额度。
3. **审批档位（edit / strict 等）必须后台运行，并循环执行 watch → 审核 → decide**（第 4、6 步）。前台运行会死锁。由主会话负责这个循环。
4. **审批分层负责**：主会话只自行处理白名单内的请求（任务范围内的安全操作），以及明显越界、应当拒绝的请求，其余按第 6 步的规则判断，拿不准的才问用户。
5. **`--access full`（跳过全部权限）只能在用户本轮明确同意后使用**，并且要同时加 `--confirm-full`。
6. **默认禁止 `git push`**。只有用户明确要求推送时才加 `--allow-push`。
7. **子会话运行期间，本会话不要改动它可能改动的文件**；并行跑多个委派时，各自负责的文件必须互不重叠。
8. **不把密码、密钥、token 写进提示词**；审批时也不得为子会话提供这些信息。
9. **结果不是事实**：子会话的报告要核实（`git diff`、读改动文件、跑测试）后，才能告诉用户「完成了」。
10. **额度用尽（退出码 5）或超时（退出码 3）时，任务没有丢**：按第 7 步在同一会话上续跑。不要立刻反复重试，也不要擅自改用主账号去做。
11. 禁止嵌套：子会话里再调用本技能或 codex-cli 都会被脚本拒绝（两个技能共用 `CLI_DELEGATE_DEPTH` 计层，`--max-depth` 默认 1）。

## 流程

### 1. 体检（每个会话第一次用时）

```bash
python3 ~/.claude/skills/cli-manager/scripts/cli_delegate.py doctor
```

看到 `结论: 可用` 才继续。未登录时，让用户在终端运行 `claude cli` 后执行 `/login`（登录只能用户自己完成）。

### 2. 写任务简报

子会话**看不到本对话的任何上下文**，简报要能独立成立。写到 scratchpad 里的文件，用 `--prompt-file` 传入（避免引号转义问题；很短的任务可以用 `--prompt`）。简报包含：

- 目标：要做成什么，完成的标准是什么
- 范围：涉及哪些文件/目录，**哪些不能动**
- 已知信息：已经查明的原因、相关文件路径、约定、要用的命令（测试/构建命令）
- 交付：希望最终报告里列出什么（改动文件、测试结果、未完成项）

范围写清楚了，后面审批时才有判断依据。

### 3. 选参数

| 用户说的 | 参数 |
|---|---|
| 「用 opus / sonnet / haiku / fable」 | `-m opus` 等；也可以用全名，如 `claude-opus-5-5`、`opusplan`、`sonnet[1m]` |
| 「思考强度高一点 / 最大 / 低」 | `-e high` / `-e max` / `-e low`（可选 low, medium, high, xhigh, max, ultracode） |
| 没指定模型或强度 | 不传，用Claude CLI的默认值 |
| 「只看不改」「分析/调研/审查」 | `-a read`：只读工具加网页搜索，其余直接拒绝，不产生审批 |
| 一般的改代码任务 | `-a edit`（默认）：文件编辑自动接受；其余需要批准的操作，包括删除、移动、复制文件和改写 git 历史/状态的命令，都交主会话审批 |
| 用户要求每一步都审 | `-a strict`：连文件编辑也交主会话审批 |
| 用户同意用自动模式 | `-a auto`：由自动模式分类器判断，被拦下的交主会话审批 |
| 用户明确说「全部放开 / 不用管权限」 | `-a full --confirm-full` |
| 无人值守、不想审批 | `--no-approval`：需要批准的操作直接拒绝，提问工具不可用 |
| 预先放行或禁止某类命令 | `--allow "Bash(npm test *)"` / `--deny "Bash(rm *)"`（预先放行的规则同样要在用户的授权范围内） |
| 限制成本/时长 | `--max-turns N`、`--max-budget-usd X`、`--timeout 秒`（默认 1800）、`--approval-timeout 秒`（单个审批的等待上限，默认 1800，超时按拒绝处理） |
| 要结构化结果 | `--json-schema '<schema 或文件>'`，结果在摘要的 `structured_output` 里 |
| 要遵守用户全局 CLAUDE.md | `--inherit-claude-md`（Claude CLI的配置目录默认没有它；项目内的 CLAUDE.md 会自动加载） |

拿不准时先加 `--dry-run` 看最终命令。

### 4. 运行

**审批档位（edit / strict / auto）**：用 Bash 的 `run_in_background: true` 启动，并用 `--id` 起一个好记的名字：

```bash
python3 ~/.claude/skills/cli-manager/scripts/cli_delegate.py run --backend claude --id <任务名> \
  --cwd "<主工作目录>" --prompt-file "<scratchpad>/task.md" -m sonnet -e high --timeout 3600
```

然后在前台**循环**执行 `watch`（Bash timeout 设为 600000）：

```bash
python3 ~/.claude/skills/cli-manager/scripts/cli_delegate.py watch <任务名>
```

`watch` 的退出码：
- `10`：有待批请求（打印编号、工具、命令或问题）。按第 6 步审核，用 `decide` 批复，然后再次 `watch`。
- `11`：等了约 9 分钟，仍在运行且没有请求。再次 `watch`。
- `0` / `1`：任务结束，打印摘要（`1` 表示出错或需要确认），转到第 5 步。

后台进程结束时也会收到通知，但审批只能靠 `watch` 及时发现，不要只等通知。

**`read` / `full` / `--no-approval`**：没有审批。预计 8 分钟内完成的任务可以前台运行（Bash timeout 600000，脚本加 `--timeout 540`）；更久的任务后台运行，结束时会收到通知，期间可用 `progress` 看进度。

其他子命令：`show [运行名|last]` 看结果；`list` 列出最近的运行，含待确认、额度用尽和重置时间；`resume` 用于带答复续跑或中断续跑（第 6、7 步）。

### 5. 读结果并核实

摘要包括：状态、工作目录、实际模型、session_id、轮数/耗时、审批统计、被拒绝的工具调用、最近的工具调用，以及子会话的最终报告。完整记录在 `~/.cli-delegate/claude-runs/<运行名>/`：`prompt.md`、`events.jsonl`、`approvals/`（每个请求、批复和日志）、`result.json`、`summary.txt`、`stderr.log`。

`run` 和 `resume` 的退出码：`0` 成功；`1` 子会话出错；`2` 参数错误或嵌套被拒；`3` 超时（可续跑）；`4` CLI/登录问题；`5` 额度用尽或被限流（可续跑）；`6` 需要用户确认（第 6 步末尾）。

核实改动（`git diff`、读文件、跑测试）后，再用中文向用户汇报：做了什么、改了哪些文件、核实结果、未完成项；如果主会话代为批准或回答过请求，也列出主要的几项。

### 6. 审批：主会话审核子会话的请求

`watch` 列出的请求有两类：**权限请求**（Bash 命令、文件写入、网络访问等）和**提问**（子会话调用 AskUserQuestion）。逐个审核，参照的是：**用户对这个委派任务的授权范围**（用户原话、任务简报），以及**主会话自己的行为规则**（凡是主会话自己做也需要先问用户的事，替子会话批准前同样要先问用户）。

**权限请求：主会话可以自己批准**（`decide <运行名> <编号> allow`）：
- 在任务范围内、作用于工作目录（或 `--add-dir` 目录）里的操作；
- 只读或可撤销的操作：查看、搜索、构建、运行测试和 lint、格式化；
- 删除或移动子会话本次自己生成的文件、构建产物、临时文件；
- 任务明确需要的依赖安装（项目内，不用 sudo），以及读取公开网页、文档。
- 同一类安全请求反复出现时，可以加 `--always` 设常驻规则：Bash 默认只放行**完全相同**的命令（含管道、分号等的命令永远不自动放行），需要放宽到某个命令前缀时，显式加 `--prefix "npm test"`；文件类放行该文件所在目录及其子目录（按真实路径判断，`/a/src` 不会匹配 `/a/src-backup`），没有路径的请求不能设常驻规则。前缀和目录都必须在授权范围内。
- 命令可以改得更安全时，用 `--updated-input '<JSON>'` 改写后批准，比如加上 `--dry-run`，或缩小作用范围。

**权限请求：主会话可以自己拒绝**（`decide ... deny -m "原因 + 可行的替代做法"`）：
- 超出任务范围，或作用于工作目录以外；
- 读取凭据和密钥（`~/.ssh`、`.env` 中的密钥、钥匙串等），或把数据发往不明地址；
- 明显是在绕过之前被拒绝的操作。

**权限请求：必须先问用户**（用 `AskUserQuestion` 问清楚后再 `decide ... --by user`）：
- 不可逆、或破坏用户已有数据的操作：删除不是子会话生成的文件，`git reset --hard`、`git clean`、强制覆盖，以及数据库或数据的批量修改；
- 对外操作：推送、发布、部署、发消息、创建 PR，以及调用会产生费用的服务；
- 改动系统或全局配置，`sudo`，安装系统级软件；
- `git commit`、打 tag、删除分支等（除非用户在任务里明确要求过）；
- 主会话拿不准的请求。

**提问（AskUserQuestion）**：
- 答案能从用户的原始要求、本对话的上下文、项目约定或稳妥的默认做法中得出：主会话自己回答，并在最后的汇报里告诉用户替他选了什么。

  ```bash
  python3 $D decide <运行名> <编号> answer --answers '{"<问题原文>": "<选项 label 或自由文本>"}'
  ```

  键必须是问题原文；多选时值用数组。
- 涉及用户的偏好、取舍或成本，并且会实质影响结果：用 `AskUserQuestion` 问用户，选项照抄，推荐项放第一个并标「(推荐)」，问题里写清是哪个委派任务。拿到答复后执行 `decide ... answer --answers ... --by user`。
- 子会话问的问题不该问（比如问能不能越界）：`decide ... deny -m "说明"`。

**要求**：
- 等待批复期间，整体超时 `--timeout` 暂停计时，只有单个请求的 `--approval-timeout` 在计时。及时批复，子会话会一直等着；单个请求等待超过 `--approval-timeout`（默认 30 分钟）会被当作拒绝。等用户回答期间也会计时，问用户时提醒这一点；需要更长时间的任务，启动时调大 `--approval-timeout`。
- 有多个待批请求时逐个审核，不要用 `all` 一次全部批准。只有全部拒绝时才可以用 `decide <运行名> all deny -m ...`。
- 主会话不得替用户回答本应由用户回答的问题，也不得自行放宽本应由用户放宽的权限。

**兜底：退出码 6（需要用户确认）**。提问被拒绝、提问工具不可用（`--no-approval`），或子会话只在报告结尾用文字提问时，摘要里会有「待确认」段，退出码为 6。处理方式与提问相同：主会话能答就自己答，答不了就问用户。然后在同一会话上续跑：

```bash
python3 $D resume <运行名> --id <新运行名> --answer "1. 选 A：……；2. ……"
```

如果需要放宽权限，加 `--allow "<规则>"` 或 `--access ...`，前提是这本身在主会话的权限内，或者已经问过用户。续跑和第 4 步一样，后台运行并循环 `watch`。

### 7. 中断续跑（额度用尽 / 超时）

已实测确认（v2.1.329）：子会话即使在第一轮就因额度用尽失败，会话记录也已经写入 `<CLI 配置目录>/projects/`，原任务提示词也在里面。`--resume` 会接在**同一个 session_id** 上继续；中途被打断的话，已经改动的文件还在磁盘上。

退出码为 5 或 3 时，摘要末尾会有「续跑」段：额度重置时间（已换算成本机时间）、建议的一次性 cron 表达式，以及续跑命令。`resume` 沿用原来的工作目录、模型、思考强度、权限档位、审批设置、放行/禁止规则和附加目录。默认续跑提示词会要求子会话先检查已完成的部分，不重复、不回滚，再继续把任务做完。

**主会话的处理方式（默认这样做，用户说不要时除外）：**

1. 告诉用户：任务中断了，Claude CLI额度在 X 点重置，会话已保存，到时会自动续跑。
2. **用 `CronCreate` 安排一次性定时**：`recurring: false`，cron 用摘要里给出的表达式（重置后约 3 分钟，本机时区）。prompt 写成能独立看懂的指令，例如：
   > Claude CLI额度已重置。用 claude-cli 续跑中断的委派任务：后台运行 `python3 ~/.claude/skills/cli-manager/scripts/cli_delegate.py resume <运行名> --id <新运行名>`，然后按技能第 6 步循环 `watch <新运行名>` 审批，直到结束；核实结果后向用户汇报。如果又是额度用尽，按新的重置时间再定一次时。

   把 CronCreate 返回的任务 ID 和实际触发时间告诉用户，用户可以要求取消（CronDelete）。
3. 定时触发后：先确认这段时间里用户没有改动相关文件，避免冲突；再按上面的方式续跑、审批、核实、汇报。
4. 续跑仍然遇到额度用尽：重复第 2 步，最多连续定 3 次，之后停下来问用户。

**备选方式**：后台运行 `... resume <运行名> --id <新运行名> --wait`，脚本会先睡到重置时间之后 90 秒再续跑（再被限流就继续等，最多 `--max-waits` 次）。如果用了审批档位，等待结束后同样要循环 `watch`。

**注意**：
- CronCreate 定时和后台等待都**只在当前主会话存活期间有效**，App 退出就失效，这一点要告诉用户。之后用 `list` 找到中断的运行，手动 `resume`。
- 周额度用尽时，重置可能在几天后。等待超过 12 小时的话，先问用户要不要等。
- `--ephemeral` 运行的会话没有保存，不能续跑。
- 续跑时可以用 `-m` / `-e` / `--timeout` 覆盖原参数，用 `-p` 换成自定义的续跑提示词。

### 8. 续聊

同一工作目录下，带上一轮的 session_id 继续：`run --cwd "<主工作目录>" --resume <session_id> -p "继续：……"`，或者 `resume <运行名> -p "……"`。加 `--fork` 会分叉出新会话，原会话保持不变。

## 配置与终端使用

- 默认位置：CLI 在 `~/.local/bin/claude`，配置目录取 `CLAUDECLI_CONFIG_DIR` → `~/.cli-delegate/config.json` 的 `claude_config_dir` → CLI 默认 `~/.claude`。可以用环境变量 `CLAUDECLI_BIN`、`CLAUDECLI_CONFIG_DIR` 改成别的位置。
- 用户也可以直接在终端交互使用 `claude`（指定了配置目录时加 `CLAUDE_CONFIG_DIR=<目录>`）；本手册描述的是会话以程序方式调用它。
